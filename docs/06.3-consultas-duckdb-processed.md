# 06.3 - Consultas DuckDB em `processed` (Etapa 5.1)

Guia prático para executar consultas SQL na camada canônica `data/processed/**/*.parquet` usando a função `query(sql)` em `src/rag/executor.py`.

Os notebooks em `notebooks/` sao a fonte de verdade dos exemplos de SQL:

- `notebooks/exploration.ipynb`: exemplos para a camada `processed`
- `notebooks/event-narrative.ipynb`: exemplos para `enriched` e joins `processed` + `enriched`

Importante: `processed` nao e uma tabela fisica do DuckDB. Ela existe apenas como view temporaria criada pela funcao `query(...)` ou manualmente via `CREATE VIEW`.

## 1. Pré-requisitos

- Pipeline de dados concluído (`data/processed` preenchido).
- Dependências instaladas (`duckdb`, `pandas`, `pyarrow`).

## 2. Passo a passo da consulta

1. Importar a função:
   ```python
   from src.rag.executor import query
   ```
2. Escrever SQL sobre a view `processed`:
   ```sql
   SELECT COUNT(*) AS total_linhas
   FROM processed
   ```
3. Executar:
   ```python
   df = query("SELECT COUNT(*) AS total_linhas FROM processed")
   ```
4. Ler o resultado no DataFrame (`df`).

Observação: a função cria uma conexão DuckDB em memória (`:memory:`) e uma view temporária `processed` apontando para `data/processed/**/*.parquet`.

Se você optar por usar `duckdb.connect(...)` ou `duckdb.sql(...)` diretamente, crie a view antes de consultar:

```python
import duckdb

with duckdb.connect(database=":memory:") as con:
    con.execute(
        "CREATE OR REPLACE VIEW processed AS "
        "SELECT * FROM read_parquet('data/processed/**/*.parquet', union_by_name=true)"
    )
    df = con.execute("""
        SELECT COUNT(*) AS total_linhas
        FROM processed
    """).df()
```

## 3. Exemplos de consulta

Os exemplos abaixo sao ilustrativos. Para exemplos mantidos e expandidos, consultar primeiro os notebooks.

### 3.1 Volume total da base

```sql
SELECT COUNT(*) AS total_linhas
FROM processed;
```

### 3.2 Linhas por código de procedimento

```sql
SELECT cod_procedimento, COUNT(*) AS linhas
FROM processed
GROUP BY cod_procedimento
ORDER BY linhas DESC;
```

### 3.3 Série mensal de custo (`competencia_ano_mes`)

```sql
SELECT
  competencia_ano_mes,
  printf('%.2f', SUM(custo_total)) AS custo_total_mes
FROM processed
GROUP BY competencia_ano_mes
ORDER BY competencia_ano_mes;
```

### 3.4 Top 10 municípios de residência por custo total

```sql
SELECT
  cod_munic_residencia,
  format('{:,.2f}', SUM(custo_total)) AS custo_total
FROM processed
WHERE cod_munic_residencia IS NOT NULL
GROUP BY cod_munic_residencia
ORDER BY SUM(custo_total) DESC
LIMIT 10;
```

### 3.5 Custo médio por sexo

```sql
SELECT
  sexo_paciente,
  format('{:,.2f}', AVG(custo_total)) AS custo_medio
FROM processed
GROUP BY sexo_paciente
ORDER BY sexo_paciente;
```

### 3.6 Monitoramento de nulos em colunas-chave

```sql
SELECT
  SUM(CASE WHEN cid_principal IS NULL OR TRIM(cid_principal) = '' THEN 1 ELSE 0 END) AS nulos_cid_principal,
  SUM(CASE WHEN custo_total IS NULL THEN 1 ELSE 0 END) AS nulos_custo_total,
  SUM(CASE WHEN competencia_ano_mes IS NULL THEN 1 ELSE 0 END) AS nulos_competencia_ano_mes
FROM processed;
```

## 4. Exemplo completo em Python

```python
from src.rag.executor import query


def main() -> None:
    sql = """
    SELECT cod_procedimento, COUNT(*) AS linhas, ROUND(AVG(custo_total), 2) AS custo_medio
    FROM processed
    GROUP BY cod_procedimento
    ORDER BY linhas DESC
    """
    df = query(sql)
    print(df)


if __name__ == "__main__":
    main()
```

## 5. Regras para escrever SQL

- Sempre consultar a view `processed`.
- Ao usar `query(...)`, nao recriar a view manualmente.
- Ao usar DuckDB puro (`duckdb.connect` ou `duckdb.sql`), criar a view `processed` antes da consulta.
- Evitar `SELECT *` em consultas analíticas grandes; preferir colunas explícitas.
- Usar filtros de período com `competencia_ano_mes`, `ano_cmpt` e `mes_cmpt` quando possível.
- Garantir agregações auditáveis (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`).
